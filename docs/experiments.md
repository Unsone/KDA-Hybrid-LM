# 实验设计（待执行）

本文件是预先约定的实验方案，不是结果报告。目前没有完整任务数据管线、训练循环或正式指标。

## 实验一：MQAR 关联回忆

示例：序列先出现 `A→1, B→7, C→3`，随后查询 B、A，模型应回答 7、1。实际使用整数 token，并在查询位置计算交叉熵和准确率。

- 比较五种 Mixer，首先固定层数、头维度、数据和训练预算。
- 变量：序列长度、键值对数量、干扰长度、状态维度。初期选择少量代表性设置，不做完整笛卡尔积。
- 键值映射和查询位置随机生成；避免无意的重复键歧义，固定可复现的验证样例。
- 每个关键设置至少三个随机种子，报告均值与波动；保留全部种子结果。
- 区分“不同长度各自训练”和“同一个模型测试长度外推”，不得混成一条曲线。
- 比较 α/β 分布、状态范数可作为诊断，不用它们替代任务指标。

首个验收目标是：训练损失下降、查询准确率提高、固定验证集可复现。此时才称为任务跑通，而不是只凭 forward 可以执行。

## 实验二：GDN 与 KDA 的门控粒度

在相同主干、数据顺序、头维度、输出 Dropout、优化器和调参预算下，只更换标量/通道门。记录实际参数量与训练时间，因为当前 KDA 的 alpha_proj 比 GDN 更大。结构匹配和参数预算匹配是不同口径，应明确说明。

报告 MQAR 准确率、收敛 token 数、验证损失及多种子波动。若 KDA 没有优势，应检查任务难度和优化后如实记录，不能按论文结论筛选结果。

## 实验三：混合语言模型

计划先用约 20M 参数验证数据、损失、优化与检查点，再尝试约 100M 参数、每配置约 1B token。语料候选为 FineWeb-Edu 子集，具体选择、许可、版本和 tokenizer 必须在实际使用前核对。

主配置：纯 Transformer、纯 GDN、7:1、3:1；比例表示线性层:全注意力层。16 层时分别可用 16 层全注意力、16 层 GDN、14+2、12+4。层位置和最终参数量必须记录。KDA 替换作为预算允许时的扩展。

- 同一 tokenizer、词表、训练/验证划分、数据顺序和有效 token 预算。
- 无数据泄漏；说明文档边界是否允许跨文档注意。
- 训练是下一 token 预测，不等于已经具备聊天或指令遵循能力。
- 验证 PPL = exp(NLL总和 / 有效token总数)，不直接平均批次 PPL。
- 记录是否共享 embedding/输出头、Norm、位置编码、卷积和各处 Dropout。
- 超参数搜索预算一致；不同结构可有各自最优超参数，不只比较一次默认试跑。

## 长上下文与针检索

needle 作为后续评估：控制真实 token 长度、插入深度、干扰内容与答案匹配方式。保存原始输出和失败样例。

短上下文训练后测更长上下文属于外推。小模型可能无法稳定遵循问答格式，因此不能把自然语言回答失败一概解释成记忆失败；与合成检索并列分析。专门训练 MQAR 的模型与预训练 LM 也不能直接按同一个 MQAR 分数比较。

## 正确性门槛

当前测试包括数学参考、因果性、梯度存在性与有限性、缓存一致性、Dropout、RoPE 和短卷积性质。它们不等同于所有自定义算子的严格 gradcheck，也不等同于 FLA 对拍。

后续分块实现：先在小尺寸比较输出和最终状态，再比较梯度；fp32/bf16 容差以实测参考误差设定。Triton 仅前向时，应明确不能直接依赖 PyTorch 自动为内核生成反向。
