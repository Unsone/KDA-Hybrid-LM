# 数值、效率与算力预算规范

当前 bench 脚本仍为空，尚无 GPU 性能结果。本文件规定未来测量口径。

## 三种计时必须分开

| 场景 | 计时内容 | 指标 |
|---|---|---|
| 训练 | 前向、损失、反向、参数更新 | 有效训练 token/s、峰值显存 |
| Prefill | 从空状态处理完整提示词 | 延迟、输入 token/s、缓存占用 |
| Decode | 已有状态时处理新 token | 每 token 延迟、生成 token/s |

内核对比只测相同 q/k/v 和门控下的算子；模型对比包含投影、MLP 等。两类结果分别报告。当前逐 token PyTorch 递推可能很慢，线性复杂度不自动等于更快的训练。

GPU 测试需预热、处理异步同步、排除首次编译并报告重复测量的中位数和波动。区分启用/禁用编译、设备、dtype、batch、序列长度、头数、头维度、块大小和缓存状态。推理采用 eval 与 inference_mode；训练计时保持真实训练模式。

## 缓存与总显存

设注意力层数 La、线性层数 Ll、KV 头数 Hkv、线性头数 H、批量 B、长度 L，每元素字节数 b：

- 常规 MHA/GQA 的 KV 约为 `B × La × Hkv × L × (Dk + Dv) × b`。
- 线性状态约为 `B × Ll × H × Dv × Dk × b`。
- 短卷积另有原始输入历史；RoPE 另有位置管理。

缓存只是总显存的一部分，不能把缓存降幅直接宣称为总显存降幅。混合网络仍含全注意力层，总缓存仍随长度增长。

作为手算示例：batch=1、16 层、每层 5 个头、Dk=Dv=128、64K=65536 token，全部缓存均为 BF16，普通 MHA 不用 GQA：

| 架构 | KV | 线性状态 |
|---|---:|---:|
| 纯全注意力 | 2.50 GiB | 0 |
| 3:1（12 线性+4 全注意力） | 0.625 GiB | 1.875 MiB |
| 7:1（14+2） | 0.3125 GiB | 2.1875 MiB |
| 纯线性 | 0 | 2.50 MiB |

这是公式计算，不是本仓库测量。当前线性状态采用 FP32，其对应状态占用是上述 BF16 假设的两倍；GQA 会减少全注意力 KV。

## 训练显存

固定推理状态不意味着训练仅保存一份 S。自动求导可能保留每一步状态和其他激活。16 层、5 头、D=128、T=2048、batch=1 时，若每步完整状态都保存，单是状态数据就约 5 GiB（BF16）或 10 GiB（FP32），未包括其他激活。

后续通过分块、重计算和专门反向优化，不能直接把推理缓存公式用于训练显存申请。

## 算力预算

粗略训练计算量可写为 `6 × 参数量 × token数`。100M 参数、1B token 得到约 `6e17 FLOPs`；持续有效 40 TFLOP/s 时约 4.17 小时。该近似没有完整覆盖特殊状态更新、注意力、重计算和实现开销，也不是显卡峰值承诺。

更可靠的预算来自实际端到端吞吐：

`小时数 = 目标token数 / 实测token每秒 / 3600`

| 假设吞吐 | 每配置 1B token | 四配置各一次 |
|---:|---:|---:|
| 5,000 token/s | 55.6 小时 | 222 小时 |
| 10,000 token/s | 27.8 小时 | 111 小时 |
| 20,000 token/s | 13.9 小时 | 55.6 小时 |
| 50,000 token/s | 5.6 小时 | 22.2 小时 |

表中为假设，不能对应到某张未经测量的 GPU。另加 MQAR、调参、验证、多种子与失败重跑。100～300 GPU 小时只是早期申请量级，不是完成保证；慢内核或多种子可能需要更多。

建议约 20M 模型先短跑测量，再决定正式规模。24GB 单卡是开发规划建议，16GB 能否容纳目标任务取决于上下文、微批量、词表、激活与反向实现。无需为 100M 模型一开始就开发分布式训练。
